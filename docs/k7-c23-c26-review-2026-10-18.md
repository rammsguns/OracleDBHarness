## Remaining finding: C24 evidence identity and source coverage

The previous explicit `param=value`, negation and wrong-owner reproductions now
behave correctly. However, the corrections still do not enforce the evidence
identity and source coverage required by Q3. These are independent reproductions
against the current `review_claims()` implementation:

| Evidence actually read | Answer tested | Actual result / defect |
| --- | --- | --- |
| Lookup 1: APP.NIGHTLY scheduler history, one row, row_limit 20 | `Increase row_limit for dba.scheduler_run_history on APP.WEEKLY to inspect its run history.` | Incorrect `next_check_cap` finding based on NIGHTLY's complete result |
| Lookup 1: APP.PKG PACKAGE BODY, source range 1–1, containing only `PACKAGE BODY PKG AS` | `The fix belongs in APP.PKG.UNREAD_MEMBER.` | No finding, although no member implementation was read |
| Lookup 1: status of APP.PKG PACKAGE BODY, VALID | `Lookup 1 shows OTHER.UNREAD is VALID.` | No finding; an unrelated object's status was never returned |
| Same status lookup | `Lookup 1 shows APP.UNREAD is VALID.` | No finding; sharing an owner is insufficient evidence |
| No lookups | `Lookup 9 shows APP.PKG is VALID.` | No finding; the referenced lookup does not exist |

Specific causes in `services/api/harness_api/copilot/claim_checks.py`:

- **Line 616, `_about()`:** any overlapping identifier component is sufficient.
  APP matches, so the different WEEKLY job is treated as NIGHTLY. This can also
  let an unrelated at-limit lookup suppress a finding for a complete result.
- **Line 451, `_unread_location()`:** a matching package returns success before
  checking any remaining member component. `_ReadUnit` also omits object type and
  source-range coverage. Reading a header or specification does not establish that
  an unread member's implementation needs a change.
- **Line 840, `_out_of_scope()`:** the negative check only catches a narrow
  same-name/different-owner situation. It does not require the claimed object to
  be supported by the cited lookup. General strings in returned cells enter its
  `seen` set, so they are not a typed identity map either.
- **Line 788, `_evidence_references()`:** an empty lookup map returns immediately,
  allowing nonexistent references when no evidence was collected.

These defects are about what evidence can support, not whether arbitrary prose
can be fully understood. An empty findings list must still never mean grounding
passed. The new harness-rendered status/error/source facts are useful progress,
but they do not bind the model's conclusions to those facts.
