### 1.1 Structural Rule Design (`claim_checks.py`)

Commit `a86124f` adds `_negated_visibility(part: str)` to complement the keyword-based `_UNSEEN`. The structural detector establishes:
- Span bounding: looks 120 characters before and after `_VISIBILITY_PREDICATE` (`visible`, `readable`, `accessible`, `invisible`, `unreadable`, `inaccessible`), delimited by punctuation `[.;!?]` and coordinating conjunctions (`and`, `so`, `but`).
- Negation and Anchor: requires `_VISIBILITY_NEGATION` (`not`, `no`, `neither`, `nor`, `none`, `nothing`, `n't`) and `_VISIBILITY_ANCHOR` (`to/from/by this/the account`, `here`, `this schema`, `from/in <OWNER>`).
- Directionality constraint: trailing negation after the predicate must accompany an action verb (`contains`, `raises`, `mentions`, `matches`), preventing unrelated negations from contaminating preceding visibility statements.
- Pre-requisite gate: fires only when lookup evidence contains a successful, zero-row `schema.*` query.

### 2.3 Analysis of Exemptions Causing Misses and False Positives

1. **Plural vs. Singular Inflection Gaps**:
   In line 3147, the exemption regex `\b(?:no\s+(?:line|object)|matches\s+no\s+object)\b` omits `s?`. Similarly, in line 3150, `\bno\s+line\b` omits `s?`. As demonstrated by probes 18 and 21, asserting `"no object visible in HARNESS_APP"` passes, but the natural plural `"no objects visible in that schema"` flags as a false positive.
2. **Object Type Synonym Gaps**:
   Line 3147 exempts `no object` and `no line`, but omits Oracle schema object types (`procedure`, `function`, `package`, `table`, `view`, `synonym`). A report stating `"In HARNESS_APP, no procedure matching ORDER_FEED was visible"` (probe 17) is falsely flagged.
3. **Visibility vs. Readability Asymmetry**:
   Line 3162 exempts `visible in [A-Z]...`, but omits `readable in` and `accessible in`. Consequently, probe 19 (`"Neither the package nor its body is readable in HARNESS_APP"`) flags as a false positive even though an identical statement using `visible in` passes.
4. **Anchor Gaps on Natural Personas**:
   `_VISIBILITY_ANCHOR` omits the preposition `for` (e.g. `"for this account"`, `"for this login"`), first-person pronouns (`"to me"`, `"by me"`), and user/session terms (`"by this user"`, `"for this session"`). While simple copula statements (`"The unit is not accessible for this login"`) are intercepted by the older `_UNSEEN`, any trailing-negation structure (`"No package readable for this login contains the message"`) completely evades detection (probe 12, 14, 16).

## 3. Focus 2: Backtick Masking Change

Commit `a86124f` altered the backtick replacement in `_absence_inferences`:

```python
# Before:
predicates = re.sub(..., lambda m: " " * len(m[0]), part)

# After (commit a86124f):
predicates = re.sub(
    r"`[^`\n]+`|\"[^\"\n]+\"|“[^”\n]+”|"
    r"(?<!\w)'(?:[^'\n]|(?<=\w)'(?=\w))+'(?!\w)|‘[^’\n]+’",
    lambda m: (
        "X" * len(m[0]) if re.fullmatch(r"`[\w$#]+`", m[0]) else " " * len(m[0])
    ),
    part,
)
```

### 3.1 Motivation and Positive Behavior

The change ensures that backticked owner identifiers (e.g. `in `HARNESS_APP``) are not blanked into whitespace (`in              `), which previously prevented `_VISIBILITY_ANCHOR` (`(?i:\b(?:from|in))\s+`?[A-Z][A-Z0-9_$#]*`?\b`) from matching the owner anchor. It also prevents backticked keywords like `` `visible` `` from supplying predicates. Existing K6 and K8 tests pass without regression (432/432 passed).

### 3.2 Regression and New False Positives: Lowercase Token Uppercasing

Replacing single backticked identifiers with uppercase `X`s (`"X" * len(m[0])`) introduces an unintended side-effect: **it forces any lowercase backticked token to become uppercase**.

Because `_VISIBILITY_ANCHOR` requires an uppercase initial letter (`[A-Z][A-Z0-9_$#]*`), unbackticked lowercase words after `in` or `from` do not match. However, when wrapped in backticks, lowercase identifiers (such as local variables, column names, or payload fields) are transformed into valid uppercase anchors:

```python
# Unbackticked (correctly ignored as non-schema anchor):
"No record in cache is readable."    -> absence_inferences: [] (PASSED)

# Backticked (artificially matches anchor `in XXXXXXX`):
"No record in `cache` is readable."  -> absence_inferences: [ClaimFinding] (FALSE POSITIVE)
"No entry in `log` was accessible."   -> absence_inferences: [ClaimFinding] (FALSE POSITIVE)
"No data in `payload` is accessible." -> absence_inferences: [ClaimFinding] (FALSE POSITIVE)
```

This creates an artificial false positive for technical prose discussing program variables or internal data structures in backticks.

## 6. Recommendations

Before deploying to production or authorizing a pooled Q5 evaluation, the following targeted refinements are recommended:

1. **Generalize Exemption Lexicon (High Priority)**:
   In `services/api/harness_api/copilot/claim_checks.py`:
   - Support plural nouns in line 3147: `\b(?:no\s+(?:lines?|objects?|procedures?|functions?|packages?|routines?|tables?)|matches\s+no\s+objects?)\b`.
   - Support plural lines and statements in line 3150: `\bno\s+(?:lines?|statements?)\b`.
   - Generalize predicate in line 3162 to include `readable`: `\b(?:visible|readable|accessible)\s+in\s+[A-Z][A-Z0-9_$#]*\b`.
2. **Expand Anchor Coverage (Medium Priority)**:
   In `_VISIBILITY_ANCHOR` (line 3106):
   - Include preposition `for`: `\b(?:to|from|by|for)\s+(?:this|the)\s+(?:account|login|user|session)\b`.
   - Include first-person referents: `\b(?:to|from|by|for)\s+me\b`.
3. **Preserve Case in Backtick Masking (Medium Priority)**:
   In line 3254, preserve original casing when masking backticked identifiers:
   ```python
   lambda m: (
       ("X" if c.isupper() else "x" if c.islower() else c for c in m[0])
       if re.fullmatch(r"`[\w$#]+`", m[0])
       else " " * len(m[0])
   )
   ```
   Or match `m[0][1:-1].upper()` only when verifying against known schema anchors, avoiding artificial uppercasing of lowercase variable/parameter names.
4. **Recognize Plan Scope in `_ABSENCE_SCOPED` (Low Priority)**:
   Add plan scopes (`execution plan`, `query plan`, `explain plan`) to `_ABSENCE_SCOPED` (line 3094) so legitimate observations about plan operations do not trip `_UNSEEN`.
5. **Support Fragment Negated Adjectives (Low Priority)**:
   Allow inherently negative visibility predicates (`invisible`, `unreadable`, `inaccessible`) accompanied by an anchor in `_negated_visibility` without requiring a redundant second negation word.

   - If findings are detected on a revisable diagnosis, the harness requests exactly **one** model revision turn via `conversation.request_revision(revision_note(findings))`.

2. **Unresolved Claim Settlement (`_settle_unresolved`)**:
   - If findings persist after revision, the harness does **not** immediately drop the answer into fallback.
   - Instead, `_settle_unresolved` attempts surgical sentence withholding via `_without_statement`, excising only the sentence containing the unsupported claim and appending a harness disclosure note (`[harness] After its one revision... Withheld a statement: ...`).

   - Bounded fallback (`render_fallback`) is triggered **only** when `_settle_unresolved` returns `None` (i.e. the offending sentence cannot be located in prose, the entire response is consumed, or findings remain after excision).
