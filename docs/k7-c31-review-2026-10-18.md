The two open issues were reproduced with the current code:

```text
No SELECT grant exists on HR.SECRET. Separately, APP.MISSING is absent but must
resolve through APP.REAL: grant SELECT on APP.REAL, or create a synonym APP.MISSING
for it. The grant is already present on APP.REAL.
```

This produces `remedy_alternative`, although the synonym addresses a missing name
unrelated to HR.SECRET. With a `dba.blocking` row for SID 42 idle 320 seconds, this
also produces `elapsed_bound`:

```text
The separate maintenance job has up to 320 seconds of work remaining,
according to its schedule.
```

The lookup says nothing about that job. These are false correction prompts, not just
missed detections. Add both as passing controls, plus changed object names, numbers and
multiple-session rows. If the same-subject relation cannot be checked reliably from
the available evidence, narrow the checker and report unsupported forms as unchecked
rather than instructing the model to change a valid claim.
