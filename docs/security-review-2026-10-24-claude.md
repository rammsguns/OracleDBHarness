## Checked and found sound

- **Token validation.** `security.py:44-49, 345-379`: `aud`, `exp`, `iss` and `sub` are all required, not just checked when present. Algorithms are pinned to `RS256`/`ES256` for OIDC and `HS256` for dev, so `none` and key-confusion attacks are excluded. The issuer is checked against configuration. Roles come from the `User` row and never from token claims (`security.py:294-299`). Disabled users are refused.
- **JWKS caching.** `security.py:105-158, 359-367`: 300 s TTL. A refresh for an unknown `kid` is rate-limited to one per 60 s. Redirects are not followed.
- **Dev auth guard.** `security.py:176-181` and `routers/system.py:51-55`: dev tokens are refused under `oidc`, and dev mode is refused outside `development` unless explicitly overridden (see C-3 for the defaults).
- **Integration credentials.** `security.py:97-102, 301-343`: 256-bit random tokens, stored as SHA-256 hashes, compared in constant time over every prefix candidate. Revocation is honoured. Integration tokens are refused on user endpoints (`security.py:273-277`). `require_grant` keeps integrations away from the database entirely (`policy.py:91-96`). The `copilot:assist` scope is enforced (`copilot/service.py:1933`).
- **Console sign-in.** `apps/web/src/oidc.ts`: authorization code flow with S256 PKCE. `state` and the verifier are kept in sessionStorage, used once, and expire after 10 minutes. The callback URL is cleared before the first await (`App.tsx:273`). The access token is held in memory only (`api.ts:4-60`). No `dangerouslySetInnerHTML` or `innerHTML` sinks were found in `apps/web/src`.
- **Per-target authorization and IDOR.** Every target route loads the grant by `(principal.user_id, profile_id)` and calls `require_grant` (`routers/targets.py`, `tuning.py`, `worksheet.py`, `runbooks.py`). Worksheet sessions are looked up by owner (`harness_worker/sessions.py:169-178`), and the execute route uses the session's own `target_id` (`routers/worksheet.py:67-70`). Executions, saved scripts, observations and copilot proposals are all filtered by owner (`history.py:53,63`; `worksheet.py:155,190`; `tuning.py:252,286`; `copilot/service.py:2133`). Audit and admin routes require `administrator` (`deps.py:462-468`).
- **Re-authorization.** Commit re-checks grant, permission and environment, and closes the session on refusal (`execution.py:505-519, 623-681`). Revoking a grant closes live sessions (`admin.py:260-279`). Every worksheet statement is authorized individually (`execution.py:727-735`).
- **Production observation rules, given a correctly labelled profile.** `policy.py:158-193` refuses worksheets, compile, session or persistent writes, and administrative risk. `admin.py:170-177` refuses enabling worksheets or mutating runbooks at creation. `policy.py:147-156` with `execution.py:347-351` require a freshly probed 19c identity. Copilot and Kiwi are refused on production (`copilot/service.py:1014-1032`). The read account's grants are minimal (`oracle/grants/harness_roles.sql:19-27`).
- **Reviewed catalog.** Every dispatched read entry under `oracle/diagnostics` is a single `SELECT`. Runbooks are `administrative` and require confirmation (`execution.py:820-829`). Kiwi may use only entries marked `@kiwi: allowed` with `read` risk; this is enforced both at load (`catalog.py:108-113`) and in the toolbox (`copilot/toolbox.py:199-204`).
- **Binds versus string building.** Catalog values are bound. Identifiers go through `quote_identifier`, which refuses `"` and NUL (`statement.py:256-274`), and object kinds come from a fixed list (`execution.py:83-93, 906-917`). The `EXPLAIN PLAN` statement id is generated server-side (`execution.py:1059-1061`). `CURRENT_SCHEMA` is quoted (`backend/oracle.py:827-844`).
- **One statement per call.** `prepare` masks literals (including `q'...'`) and comments, and refuses multiple statements, client commands and substitution variables (`statement.py:187-241`). The engine treats `UNKNOWN` as a writing kind (`engine.py:56-62`).
- **Row and time limits.** Caller limits can only narrow the configured ones (`types.py:142-153`). Catalog `row_limit` is capped at `max_rows` (`execution.py:928-930`). The driver `call_timeout` and a total deadline are both applied (`backend/oracle.py:325`). Fetch is bounded (`backend/oracle.py:515-536`). Kiwi applies a per-tool row cap (`toolbox.py:295-310`).
- **Pack-licensed views excluded.** No `DBA_HIST_*`, ASH, SQL Monitor, `DBMS_SQLTUNE`, `DBMS_WORKLOAD_*`, `DBMS_ADDM` or `DBMS_ADVISOR` reference appears anywhere under `oracle/` or `services/` (searched). The DBA overview says so explicitly (`routers/targets.py:361-365`).
- **Secret handling.** File locators are contained by path relationship, not string prefix (`secrets.py:286-294`). `ConnectionSpec.password` has `repr=False`, and error details use `spec.redacted()` (`backend/base.py:39-50`; `backend/oracle.py:800-803`). Worksheet statement text is not retained by default, only fingerprinted with literals masked (`execution.py:1202`; `statement.py:283-292`). Bind values are never persisted (only `bind_names`). Prompt logging is off by default and produces a warning when on (`config.py:85, 224-228`).
- **Outcome-unknown semantics and recovery.** `_fail_execution` keeps uncertain writes as `outcome_unknown` (`execution.py:1319-1346`). Restart reconciliation never redispatches, resolves never-dispatched work to `cancelled` and interrupted reads to `failed`, and leaves interrupted writes as `outcome_unknown` (`recovery.py:111-150`). Store ownership is fenced before writes and commits (`execution.py:233-262, 1216-1243`). Operator findings never overwrite the state (`admin.py:445-512`).
- **Local-only copilot.** The settings validator refuses `anthropic` while `local_only` is on (`config.py:148-158`), and `create_provider` checks again (`copilot/provider.py:668-674`). The local endpoint must be plain http to a loopback address: it is resolved and pinned at startup, and a transport refuses any other host and any redirect (`copilot/local.py:83-173`).
- **Kiwi prompt-injection containment.** Tool calls are bound to the request's `profile_id`, which the model cannot change. They re-run `require_grant` and `run_catalog_operation` as the requesting user on every call (`toolbox.py:254-310`). There is no free-form SQL tool. Unknown tools are refused and audited. Steps, tool calls, tokens, bytes and wall time are all bounded (`config.py:94-118`). Proposals only change an editor buffer.
- **Deployment basics.** The API runs as non-root uid 10001 (`Dockerfile.api:24-27`). Host ports are bound to 127.0.0.1 (`compose.yaml:81,90`). PostgreSQL is not published. Secrets are mounted as files, and the metadata password is read from a file rather than the URL.

## Verdict

**No blocking findings for a test-stand-in pilot.**

With the compose deployment as shipped (`HARNESS_AUTH_MODE=oidc`, a required endpoint allowlist, copilot off by default), I found no path from an authenticated non-administrator to a write on a correctly labelled production target, and none that bypasses authentication. Fix C-1 and C-2 before any real production target is registered: C-1 because the observation-only guarantee depends on an unvalidated free-text label, and C-2 because administrative access changes leave no audit trail. C-3 through C-8 should be resolved before the pilot widens beyond a stand-in.
